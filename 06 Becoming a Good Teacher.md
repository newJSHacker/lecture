# 06 Becoming a Good Teacher

The rest of this repository says **what** to teach (curriculum, lectures, theses). This note and the folder [[Teaching/00 How to Use These Notes]] say **how to become good at teaching it**.

A strong IGWT instructor is not only a graphics engineer who talks. They design learning, run rooms, give feedback that changes work, and keep students able to try again after failure.

## Teaching philosophy (one page)

Use the five pillars from [[02 Curriculum Design Advice]]:

1. Theory (Why?)
2. Demonstration (How?)
3. Hands-on practice (Do it yourself)
4. Project (Apply)
5. Assessment (Prove)

Add four instructor habits that those pillars assume but do not name:

6. **Diagnosis.** Watch work, not faces. A nodding room can still be lost.
7. **Feedback loops.** Students must act on comments before the next grade.
8. **Psychological safety.** People will not live-code if humiliation is likely.
9. **Improvement.** Record one thing that failed each week. Change one thing next week.

Graphics, WebGL, shaders, and interaction are learned by building. Teaching them is learned the same way: plan, try, watch students, revise.
