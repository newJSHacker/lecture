# 21 — Writing assignments

A homework is a designed practice, not a pile of leftover slides. Bad homework is either trivial busywork or a second unpublished course.

## Properties of a good weekly assignment

1. **Continues the lab object** when possible (same repo, next function)
2. **Has a must layer** that an average prepared student can finish in the advertised hours
3. **Has a stretch** that is clearly optional
4. **Mixes doing and explaining** (4–6 hours code + 3 short written items is a good default)
5. **Is testable or screenshotable**
6. **Does not require unpublished lecture jokes**
7. **Names the integrity rule again** (one line)

Advertised hours must be real. If you would need 12 hours, you advertised wrong or the starter is wrong.

## Written questions that work

- A picture to mark
- “Here is a wrong student explanation. Fix it.”
- “Give a degenerate input and what your program does”
- “Complexity of step 2 after the sort, and why”
- “Paste a 10-line function and comment the invariant”

Avoid:

- “Research Three.js and write 800 words”
- “Read the chapter and summarize”
- Questions whose only answer is a definition you will never use again

## Code questions that work

- Implement `onSegment` given `orient`
- Add a fixture that currently fails
- Change one constraint (“no extra allocations in the inner loop” or “handle duplicates”)
- A refactor: extract the kernel from the draw loop

Avoid:

- “Build a game”
- “Match this screenshot exactly” with an underspecified camera
- Hidden dependencies on a TA’s machine path

## Starters

A starter should compile, contain `TODO`s, and include **one failing test** or a clearly wrong picture. An empty folder is not a starter. A finished solution with `TODO` comments is a cruelty.

## Homework vs lab

Lab: first contact, pairs allowed if you say so, help in the room.

Homework: they should be able to finish the must layer alone. If they cannot, the lab did not end at the right place.

## Late days

A small bank of late days (for example 3 × 24 hours per term) reduces email and panic. State whether they apply to projects. Do not combine mystery extensions with a public “no late work” line.

## Returning

Comments before the next related work. A key or a short walkthrough after the deadline, or the homework is a black box.

## Multi-week projects

See [[Teaching/09 Assessment Design]] for milestones. The weekly homework in project season should be **artifacts** (risk list, draft figure, failing test), not new feature lists.

## Reading assignments

If you assign a paper or a chapter:

- Give 3 questions they must answer
- Tell them what to skip
- Use 10 minutes of class on the questions, or they will not read

A 40-page paper with “please read” is a wish.

## Exercise
