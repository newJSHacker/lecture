# 19 — Checklists and templates

Print these. Fill them. Do not admire them.

## A. Week-before-class

- [ ] Learning goal is one observable sentence
- [ ] Starter runs on a clean clone
- [ ] Solution exists in a private place
- [ ] Lab has a screenshot of “done”
- [ ] Quiz: 5 items + key
- [ ] Demo backup (recording or known-good commit)
- [ ] Rubric matches the spec
- [ ] TAs briefed on the week’s misconception
- [ ] Accommodation list checked (quietly)
- [ ] HDMI / audio / markers work

## B. Day-of lecture

- [ ] Room 10 minutes early
- [ ] Editor zoom 140%+
- [ ] Opening retrieval ready
- [ ] Board plan: goal + invariant strip
- [ ] Student attempt exists in the middle
- [ ] Ending: lab hook, not “any questions?”

## C. Lab open

- [ ] Success condition said in one sentence
- [ ] Expected bug named
- [ ] Pair roles if pairing
- [ ] Queue rule for help
- [ ] You will circulate, not sit

## D. Desk visit (4 minutes)

- [ ] “Show me what it does”
- [ ] “What did you try?”
- [ ] One next action
- [ ] Leave

## E. Help request (students)

```
Expected:
Got:
Tried (2):
Hypothesis:
```

## N. TA escalation

Escalate immediately: harassment, safety, cheating case, medical crisis, “the starter is broken for everyone.”

Do not escalate: one student forgot `npm install` (unless it is everyone).
